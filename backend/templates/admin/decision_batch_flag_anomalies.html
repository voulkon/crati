What this does

  1. Selects candidate decisions whose recorded amount is in the min–max range (an AFM/KAE rendered as a number has 8–9 digits), optionally restricted to an import-date window.
  2. For each amount field, compares the value against the decision's counterpart ΑΦΜ/ΚΑΕ values — exact equality, zero cents only (a €99,370,338.00 amount next to AFM 099370337 is a legitimate amount and is not flagged).
  3. Writes the marker invalid_amount_reason / invalid_amount_value / invalid_amount_flagged_at on matching fields — never a monetary value. The real amount is unknown, so verified_amount is left untouched and the bogus figure is excluded from every monetary total.

⚠️ Dry run is on by default. Uncheck it to actually write the marker. The operation is idempotent (re-running rewrites the same reason/value) and reversible with the Clear option or the “Clear non-monetary flag” list action.

This form runs python manage.py fix_amount_anomalies — the same code path as the CLI — bounded to the given limit. For very large sweeps run the command directly in the container.
